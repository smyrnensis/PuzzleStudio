
# レベルデータJSON仕様書

## 1\. 概要

本仕様書は、ゲームの各レベル（ステージ）の構造を定義するJSONファイルのフォーマットを定めます。レベルデータには、盤面の初期配置、クリア条件などのレベル固有の状態、およびオブジェクトと文字を対応付ける凡例が含まれます。

-----

## 2\. 基本構造

レベルデータは、メタ情報、グローバル変数、凡例、そして単一の盤面マップから成ります。オブジェクトの所属レイヤーや衝突判定はオブジェクト自体の定義で管理されるため、レベルデータ側では盤面の見た目を定義することに集中できます。

```json
{
  "id": "level_02",
  "title": "level_02",
  "width": 5,
  "height": 5,
  "global_state": {
    "moves": 0,
    "required_goals": 2
  },
  "legend": {
    "P": ["Player"],
    "W": ["Wall"],
    "#": ["Box"],
    ".": ["Goal"],
    "X": ["Goal", "Box"],
    " ": []
  },
  "map": [
    "WWWWW",
    "WP.WW",
    "W.#.W",
    "W..XW",
    "WWWWW"
  ]
}
```

-----

## 3\. フィールド詳細

### メタデータ

| フィールド | 型 | 必須 | 説明 |
| :--- | :--- | :--- | :--- |
| `id` | string | ○ | レベルを一位に識別するID。 |
| `title` | string | × | UIに表示されるレベル名。 |
| `width` | Int | ○ | 盤面の幅（グリッド数）。 |
| `height` | Int | ○ | 盤面の高さ（グリッド数）。 |

### global\_state

そのレベルが開始される際のグローバル変数の初期値を定義するオブジェクトです。

  * **例**: `{ "moves_limit": 30, "is_key_found": false }`

### legend (凡例)

`legend`は、`map`で使用される文字と、それに対応する**オブジェクト名の配列**を関連付けます。

  * **キー**: `map`内で使用する1文字のシンボル。
  * **バリュー**: 対応するオブジェクト名の**配列**。`["Player"]`のように単一の場合も、`["Goal", "Box"]`のように複数の場合も必ず配列で記述します。空のセルは空配列`[]`で表現します。

### map (盤面データ)

`map`は、盤面の状態を単一のASCIIアート形式で表現する文字列の配列です。

  * 各文字は`legend`で定義された1つまたは複数のオブジェクトに対応します。
  * ゲームエンジンは、この`map`と`legend`を読み込み、各オブジェクトの定義（所属レイヤーやプロパティなど）に従って、自動的に正しいレイヤー構造を持つゲーム盤面を構築します。

-----

## 4\. 複数オブジェクトの配置例

`legend`で1つのキーに複数のオブジェクトを割り当てることで、同じセルに複数のオブジェクトを初期配置できます。

例えば、上記の基本構造の例では `X` という文字を使用しています。

```json
  "legend": {
    ...,
    "X": ["Goal", "Box"],
    ...
  },
  "map": [
    ...,
    "W..XW",
    ...
  ]
```

パーサーは`map`内の`X`を読み取ると、その位置(`x:3, y:3`)に`Goal`オブジェクトと`Box`オブジェクトの両方を配置します。各オブジェクトがどのレイヤーに描画されるかは、オブジェクト自身の定義に従うため、レベルデザイナーはレイヤー構造を意識することなく直感的にマップを設計できます。
