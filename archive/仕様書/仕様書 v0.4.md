# ルールベース・グリッドパズルゲームフレームワーク仕様書

## 1. 概要

### 1.1. ドキュメントの目的

本仕様書は、Godotエンジン (4.4.1 stable) 上で動作する、ターンベース・グリッドベースパズルゲームを開発するための共通フレームワークの設計を定義します。

### 1.2. 設計哲学

#### データとしてのルール

- ゲームロジックは管理しやすいルールの集まりとして表される
- ルールは「状況Aを状況Bに変換する」パターン置換として記述
- 開発者はPuzzleScript文法でルールを記述

#### 制約による明確性

- グリッドベースのみ：すべてのゲーム要素は格子上に配置
- ターンベース：リアルタイム要素は排除
- 整数のみ：float型は使用せず、Bool型とInt型のみでゲーム状態を表現

#### 汎用性
- 汎用的なゲームフレームワークの部分と個別のゲームの情報を分離
- データ(ルール、レベル、スプライト)を入れるだけでゲームが完成するフレームワーク
#### まとめると、
ほぼほぼPuzzleScript。PuzzleScriptの哲学をGodot上で再現し、インターフェイスなどPuzzleScriptではどうしても足りない部分にも手が届くようにする。

## 2. アーキテクチャ

### 2.1 GameData
- オブジェクトの定義
- ルールデータ
- レベルデータ
- UIデータ(スプライト、効果音等)
### 2.2 GameState

```
State = GameState + GlobalState + PuzzleState + History
```

- GameState: ゲーム全体で共有される設定・進行状況
- GlobalState: 特定のレベルにおけるセルに割り当てられない状態
- LevelState: 特定レベルにおける盤面の状態
- History: undoのために記録されるプレイヤーの履歴
#### GlobalState
- StringあるいはIntで、任意のセルから参照可能
#### LevelState
- LevelStateは複数のLayerのリストからなる。
- 1つのLayerはcollison: Boolおよびステージの各グリッドから構成される。
- グリッドはObjectのリストによって指定される。collision =  Trueならばこのリストは1つまでしか要素を持たない。collison = Falseならばいくらでも要素を持つことができる。
- グリッドは整数座標(x, y)で表現
#### Objects
- オブジェクトはName: Stringで区別され、さらにlayer, property, tagをもつ
- collision: Bool は1つのセルにそのオブジェクトを複数おけるか、それとも1つしか置けないかを決める
- layer: Intは描写における優先順位を表す
- propertyは複数のオブジェクトに共通する性質を表す (例: "Player"と"Box"はともに"movable"というpropertyをもつ)
- tagは1つのオブジェクトのバリエーションを作り、Name:tag1:tag2という形式で表される (例: "Player:move:left", "Player:move:right", "Player:stop")
#### History
- 過去のLevelStateの記録

#### Rule（ルール）

- RuleParserはPuzzleScript形式のルールテキストからjasonデータであるRuleDataを生成する。
- RuleProcessorはRuleData形式のルールを読み込んで、GameStateを更新する。
- GameManagerは入力の処理やレベルの開始・終了など、各ターンのルールの適用以外を担う
### 2.2. 実行フロー

1. **Input**: プレイヤーからの入力を受信
2. **Rule Application**: ルールを順次適用
3. **State Update**: 新しいGameStateが確定
4. **Render**: 新しい状態を画面に反映
### 2.3. コンポーネント

- **GameManager**: ゲーム進行の管理と入力処理
- **RuleProcessor**: ルールの解釈と適用
- **PuzzleScriptParser**: PuzzleScript → JSON変換

## 3. ルールシステム

### 3.1. ルールの本質

ルールは**パターンマッチング**と**置換**の組み合わせ：

```
Rule: Pattern_Before → Pattern_After
```

- **Pattern_Before**: マッチング対象となる盤面パターン
- **Pattern_After**: 置換後の盤面パターン

### 3.2. ルール適用原理

1. **マッチング**: 現在の盤面からPattern_Beforeにマッチする箇所を検索
2. **検証**: 追加条件（インベントリ、フラグなど）をチェック
3. **置換**: マッチした箇所をPattern_Afterで置き換え
4. **反映**: 変更を新しいゲーム状態に反映
