# PuzzleMaker ブロック設計書

> バイブコーディング（AI実装 + 非エンジニア管理）のための設計書。
> 詳細な内部仕様は `フレームワーク計画.md` を参照。本書はそれを「管理者が何を見るか」の視点で再構成したもの。

---

## 1. 設計方針

### バイブコーディングにおける役割分担

| あなた（管理者） | AI（実装者） |
|:---|:---|
| 各ブロックの完成をテストで確認 | ブロック内部の全コードを実装 |
| game.json / level.json の作成・確認 | テストの作成と実行 |
| ブラウザでの動作確認 | バグの発見と修正 |

### ブラックボックスの原則

フレームワークを **4つのブロック + 1つのデータ層** に分ける。各ブロックの中身は触らない。確認するのは **入力と出力だけ** 。

### データの性質: 全て離散

このシステムでは **全てのデータは離散（整数・列挙・真偽値）** である。

唯一の例外はキーボード入力の「いつ押されたか」という時間情報だが、これは Input ブロックが連続→離散に変換して以降、システム内に連続値は一切存在しない。

## 2. 全体構成図

```
  Keyboard (continuous)
       |
       v
+--------------+
| Block A      |
| Input        |  continuous -> discrete
+--------------+
       | InputEvent (discrete)
       v
+--------------+
| Block B      |
| Engine       |  discrete -> discrete (pure function)
|              |  GameState = f(InputEvent, GameState)
+--------------+
       | GameState (discrete)
       v
+--------------+
| Block C      |
| Renderer     |  discrete -> display
+--------------+
```

### パイプラインとして見る

```
[連続] → Input → [離散] → Engine → [離散] → Renderer → [画面]
```

- Input の出口以降、連続データは存在しない
- Engine は純粋関数: 同じ入力には必ず同じ出力
- Renderer は受け取った離散状態を表示するだけ

### App Shell（接着コード）

`apps/playground/src/main.ts` が上の3ブロックを繋ぐ。約30行。

## 3. Block A: Input（入力）

### 概要

| 項目 | 内容 |
|:---|:---|
| **場所** | `packages/input/` |
| **役割** | 連続的なキーボードイベントを離散的な InputEvent に変換 |
| **依存** | なし |

### なぜ独立ブロックなのか

キーボード入力は本質的に時間軸（連続）を持つ。例えば:
- キーを押す **タイミング** は連続的
- キーの **長押し** はリピートイベントを生む

しかしこのゲームはターンベースであり、必要なのは「何を押したか」という離散的な事実だけ。Input ブロックの責務は、この **連続→離散の変換** を行い、以降のシステムに連続データを一切渡さないこと。

### 公開インターフェース

```typescript
const input = new InputAdapter({
  // キーバインド設定（省略可、デフォルトあり）
  bindings: {
    up:      ["ArrowUp", "KeyW"],
    down:    ["ArrowDown", "KeyS"],
    left:    ["ArrowLeft", "KeyA"],
    right:   ["ArrowRight", "KeyD"],
    action:  ["Space"],
    wait:    ["Period"],
    undo:    ["KeyZ"],
    redo:    ["KeyY"],
    restart: ["KeyR"],
  }
});

// コールバック: 離散化された入力イベントを受け取る
input.onInput((event: InputEvent) => {
  // event は { type: "move", direction: "right" } など
});

input.start();   // リスニング開始
input.stop();    // リスニング停止
```

### 入力と出力

| | 型 | 内容 |
|:---|:---|:---|
| **入力** | KeyboardEvent（連続） | ブラウザのキーボードイベント |
| **出力** | InputEvent（離散） | 下記の6種類のいずれか |

### InputEvent の種類

| type | 意味 | 追加データ |
|:---|:---|:---|
| `"move"` | 移動 | `direction`: `"up"` / `"down"` / `"left"` / `"right"` |
| `"action"` | アクションボタン（将来用） | なし |
| `"wait"` | 待機（ターンスキップ） | なし |
| `"undo"` | 1手戻す | なし |
| `"redo"` | 1手進める | なし |
| `"restart"` | レベル最初から | なし |

### 検証方法

```bash
pnpm -C packages/input test
```

## 4. Block B: Engine（ルールエンジン）

### 概要

| 項目 | 内容 |
|:---|:---|
| **場所** | `packages/engine/` |
| **役割** | JSON ゲームデータ + InputEvent → 新しい GameState |
| **外部依存** | なし（純粋な TypeScript のみ） |

### 核心的な性質

```
GameState = f(InputEvent, GameState)
```

Engine は **純粋関数** 。同じ InputEvent と同じ GameState を渡せば、必ず同じ結果を返す。ブラウザにも時計にもネットワークにも依存しない。

### 公開インターフェース

Engine ブロック全体の窓口は `GameManager` クラス1つだけ。

```typescript
// ── 初期化 ──
const game = new GameManager(gameDataJson);
game.loadLevel(levelDataJson);

// ── 入力処理（全てこの1メソッドに集約）──
const result = game.processInput({ type: "move", direction: "right" });

// ── 出力 ──
result.state;    // GameState: 現在の盤面（離散）
result.phase;    // "playing" | "won"（列挙）
result.effects;  // Effect[]: サウンド・メッセージなど
result.changed;  // boolean: 盤面に変化があったか

// ── 状態の読み取り ──
game.getState();  // 現在の GameState
game.getPhase();  // 現在のフェーズ
```

### 入力と出力

| | 型 | 内容 |
|:---|:---|:---|
| **入力（初期化時）** | GameData | game.json の内容（離散データ） |
| **入力（初期化時）** | LevelData | level-XX.json の内容（離散データ） |
| **入力（毎ターン）** | InputEvent | Block A の出力（離散） |
| **出力** | TurnResult | GameState + Phase + Effects（全て離散） |

### GameState の構造

```
GameState（全て離散値）
├── globalState   ... Map<string, int | bool | string>
├── puzzle          ... 2次元配列。各セル = 文字列のリスト
├── width         ... 整数
└── height        ... 整数
```

- `puzzle[y][x]` → `["Floor", "Player:down"]` のような文字列配列
- 浮動小数点は一切使わない

### 内部モジュール（知らなくてOK）

| モジュール | 役割 |
|:---|:---|
| ObjectDB | オブジェクト定義の登録・プロパティ解決 |
| LevelLoader | ASCII マップ → 初期 GameState の構築 |
| PatternMatcher | ルールのパターンをグリッド上で検索 |
| RuleProcessor | ルールを適用して新しい GameState を生成 |
| HistoryManager | undo/redo 用の状態スナップショット管理 |
| ユーティリティ群 | オブジェクト文字列操作、グリッド操作など |

### 検証方法

```bash
pnpm -C packages/engine test
# 全テスト通過 → このブロックは完成
```

## 5. Block C: Renderer（描画）

### 概要

| 項目 | 内容 |
|:---|:---|
| **場所** | `packages/renderer/` |
| **役割** | 離散的な GameState を受け取り、Canvas に描画する |
| **依存** | Block B (Engine) の型定義のみ |

### 核心的な性質

Renderer は **出力専用** 。入力の処理は一切しない。GameState という離散データを受け取って、それを画面に表示するだけ。

### 公開インターフェース

```typescript
const renderer = new GameRenderer({
  canvas: document.getElementById("game"),
  cellSize: 48,                        // 1マスのピクセルサイズ
  objectDefinitions: gameData.objects,  // 色・レイヤー情報
});

// 描画（これだけ）
renderer.render(gameState);

// リサイズ
renderer.resize(width, height);
```

### 入力と出力

| | 型 | 内容 |
|:---|:---|:---|
| **入力（初期化時）** | ObjectDefinition[] | 各オブジェクトの色・レイヤー情報 |
| **入力（毎フレーム）** | GameState | 描画すべき盤面（離散） |
| **出力** | Canvas 描画 | 画面上のピクセル |

### 内部モジュール（知らなくてOK）

| モジュール | 役割 |
|:---|:---|
| CanvasRenderer | Canvas 2D API での描画処理 |
| SpriteManager | オブジェクト定義から色・見た目を管理 |

### 検証方法

```bash
pnpm -C packages/renderer test
```

## 6. App Shell（接着コード）

### 概要

| 項目 | 内容 |
|:---|:---|
| **場所** | `apps/playground/` |
| **役割** | 3つのブロックを繋ぐ |
| **コード量** | 約30行 |

### コードの全体像

```typescript
import { GameManager } from "@puzzlemaker/engine";
import { InputAdapter } from "@puzzlemaker/input";
import { GameRenderer } from "@puzzlemaker/renderer";

async function main() {
  // 1. JSON を読み込む
  const gameData = await fetch("./game.json").then(r => r.json());
  const levelData = await fetch("./level-01.json").then(r => r.json());

  // 2. 3つのブロックを初期化
  const game = new GameManager(gameData);
  game.loadLevel(levelData);

  const renderer = new GameRenderer({
    canvas: document.getElementById("game") as HTMLCanvasElement,
    cellSize: 48,
    objectDefinitions: gameData.objects,
  });

  const input = new InputAdapter();

  // 3. パイプラインを接続: Input → Engine → Renderer
  input.onInput((event) => {
    const result = game.processInput(event);
    renderer.render(result.state);
    if (result.phase === "won") {
      alert("クリア！");
    }
  });

  // 4. 初回描画 & 開始
  renderer.render(game.getState());
  input.start();
}

main();
```

### 検証方法

```bash
pnpm dev          # ブラウザで遊べる
pnpm build        # dist/index.html が生成される
```

## 7. Data Layer: ゲームデータ

### 概要

| 項目 | 内容 |
|:---|:---|
| **場所** | `games/` |
| **役割** | ゲームの内容を定義する純粋な JSON ファイル |

ゲームのルールもレベルも全てデータ。コードを一切変えずに、JSON だけで新しいパズルを作れる。全て離散値。

### ファイル構成

```
games/
└── sokoban/               # ゲームごとのフォルダ
    ├── game.json           # ゲーム定義（1ゲームに1つ）
    └── levels/
        ├── level-01.json   # レベル1
        └── level-02.json   # レベル2
```

### game.json の構造

```jsonc
{
  "name": "ゲーム名",
  "description": "ゲームの説明",

  // ゲーム全体の初期変数（全て離散値: 整数・真偽値・文字列）
  "initialGlobalState": {
    "_input_direction": "none",
    "moves": 0
  },

  // オブジェクト定義: ゲームに登場するもの全て
  "objects": [
    {
      "name": "Wall",                   // 名前（文字列）
      "layerId": 1,                     // 描画レイヤー（整数）
      "properties": ["Solid"],          // 性質（文字列リスト）
      "tags": {},                       // 状態バリエーション
      "sprite": { "color": "#404040" }  // 見た目
    }
    // ... Player, Box, Goal なども同様
  ],

  // ルールグループ: ゲームの振る舞いを定義
  "ruleGroups": [
    {
      "name": "player_movement",
      "application": "once",
      "rules": [ /* ... */ ]
    }
  ],

  // 毎ターン実行するグループの順番
  "turnSequence": ["player_movement", "box_goal_check"]
}
```

### level-XX.json の構造

```jsonc
{
  "name": "レベル名",

  // 凡例: 1文字 → オブジェクトの配列
  "legend": {
    "W": ["Wall"],
    "P": ["Floor", "Player"],
    "#": ["Floor", "Box"],
    ".": ["Floor", "Goal"],
    " ": ["Floor"]
  },

  // ASCII アートでマップを定義
  "map": [
    "WWWWW",
    "WP  W",
    "W # W",
    "W . W",
    "WWWWW"
  ],

  // クリア条件
  "winConditions": [
    { "type": "no", "object": "Box" }
  ]
}
```

### クリア条件の種類

| type | 意味 | 例 |
|:---|:---|:---|
| `"all"` | 指定オブジェクトが全て指定場所にある | 全 Box が Goal の上 |
| `"no"` | 指定オブジェクトが盤面にない | Box が0個 |
| `"some"` | 1つ以上が指定場所にある | 1つ以上の Box が Goal の上 |
| `"global"` | グローバル変数の条件 | score >= 100 |

## 9. ブロック間の契約（インターフェース一覧）

ブロック間でやり取りされるデータの一覧。全て離散値。

### Input → Engine

| 型 | 内容 |
|:---|:---|
| `InputEvent` | `{ type: "move", direction: "right" }` などの離散イベント |

### Engine → Renderer

| 型 | 内容 |
|:---|:---|
| `GameState` | puzzle（盤面）+ globalState（変数）+ width/height |
| `Effect[]` | サウンド再生、メッセージ表示などの副作用 |
| `GamePhase` | `"playing"` or `"won"` |
| `ObjectDefinition[]` | 描画に必要な色・レイヤー情報（初期化時のみ） |

### JSON → Engine

| 型 | 内容 |
|:---|:---|
| `GameData` | game.json の内容そのまま |
| `LevelData` | level-XX.json の内容そのまま |

### ブロック間にデータは逆流しない

```
Input → Engine → Renderer
```

データは常にこの一方向に流れる。Renderer から Engine に戻ることも、Engine から Input に戻ることもない。
