# レベルデータ仕様書

> 詳細な型定義は `docs/フレームワーク計画.md` セクション 5.5 を参照。
> JSON スキーマは `docs/フレームワーク計画.md` セクション 6.2 を参照。

---

## 1. 概要

本仕様書は、ゲームの各レベル（ステージ）の構造を定義する JSON ファイルのフォーマットを定める。レベルデータには、盤面の初期配置、クリア条件、およびオブジェクトと文字を対応付ける凡例が含まれる。

---

## 2. 基本構造

レベルデータは、メタ情報、グローバル変数初期値、凡例、盤面マップ、クリア条件から成る。オブジェクトの所属レイヤーや描画順序はオブジェクト自体の定義で管理されるため、レベルデータ側では盤面の配置を定義することに集中できる。

```typescript
interface LevelData {
  readonly name?: string;
  readonly legend: Legend;
  readonly map: readonly string[];
  readonly winConditions: readonly WinCondition[];
  readonly initialGlobalState?: Readonly<Record<string, GlobalValue>>;
}
```

**JSON 例:**

```json
{
  "name": "Level 1 - First Steps",
  "legend": {
    "W": ["Wall"],
    "P": ["Floor", "Player"],
    "#": ["Floor", "Box"],
    ".": ["Floor", "Goal"],
    "*": ["Floor", "Goal", "BoxOnGoal"],
    " ": ["Floor"]
  },
  "map": [
    "WWWWW",
    "WP  W",
    "W # W",
    "W . W",
    "WWWWW"
  ],
  "winConditions": [
    { "type": "no", "object": "Box" }
  ],
  "initialGlobalState": {
    "moves": 0,
    "pushes": 0
  }
}
```

## 3. フィールド詳細

### メタデータ

| フィールド | 型 | 必須 | 説明 |
|:---|:---|:---|:---|
| `name` | `string` | × | UI に表示されるレベル名。 |

**注**: 盤面のサイズ（幅・高さ）は `map` の内容から自動計算されるため、明示的なフィールドは不要。

### initialGlobalState

そのレベルが開始される際のグローバル変数の初期値を定義するオブジェクト。`GameData.initialGlobalState` とマージされ、レベルデータの値が優先される。

**例:**
```json
{ "moves": 0, "pushes": 0, "moves_limit": 30 }
```

### legend（凡例）

`legend` は、`map` で使用される文字と、それに対応するオブジェクト名の配列を関連付ける。

```typescript
type Legend = Readonly<Record<string, readonly string[]>>;
```

- **キー**: `map` 内で使用する 1 文字のシンボル
- **バリュー**: 対応するオブジェクト名の **配列**。`["Player"]` のように単一の場合も、`["Goal", "Box"]` のように複数の場合も必ず配列で記述する。空のセルは `["Floor"]` のように背景オブジェクトで表現する

### map（盤面データ）

`map` は、盤面の状態を単一の ASCII アート形式で表現する文字列の配列。

- 各文字は `legend` で定義された 1 つまたは複数のオブジェクトに対応する
- **全行が同じ長さでなければならない**
- ゲームエンジンは `map` と `legend` を読み込み、各オブジェクトの定義（`defaultTags` 等）を適用して初期 GameState を構築する

### winConditions（クリア条件）

レベルのクリア条件を定義する配列。複数指定時は AND（すべて満たす必要がある）。

```typescript
type WinCondition =
  | { type: "all"; object: string; on: string }
  | { type: "no"; object: string }
  | { type: "some"; object: string; on: string }
  | { type: "global"; variable: string; op: ComparisonOp; value: GlobalValue };
```

| タイプ | 説明 | 例 |
|:---|:---|:---|
| `"all"` | 指定オブジェクトが**全て**指定オブジェクトと同じセルにある | 全ての Box が Goal の上にある |
| `"no"` | 指定オブジェクトが盤面に**1つも存在しない** | Box が盤面から全て消えた（BoxOnGoal に変換された） |
| `"some"` | 指定オブジェクトが**1つ以上**指定オブジェクトと同じセルにある | いずれかの Key が Door の上にある |
| `"global"` | グローバル変数の条件 | `score >= 100` |

**例:**

```json
"winConditions": [
  { "type": "all", "object": "Box", "on": "Goal" },
  { "type": "no", "object": "Box" },
  { "type": "global", "variable": "score", "op": ">=", "value": 100 }
]
```

## 4. 複数オブジェクトの配置例

`legend` で 1 つのキーに複数のオブジェクトを割り当てることで、同じセルに複数のオブジェクトを初期配置できる。

```json
{
  "legend": {
    "X": ["Goal", "Box"],
    "*": ["Floor", "Goal", "BoxOnGoal"]
  },
  "map": [
    "WWWWW",
    "W..XW",
    "W*P W",
    "WWWWW"
  ]
}
```

パーサーは `map` 内の `X` を読み取ると、その位置に `Goal` と `Box` の両方を配置する。各オブジェクトがどのレイヤーに描画されるかは、オブジェクト自身の `layerId` 定義に従うため、レベルデザイナーはレイヤー構造を意識することなく直感的にマップを設計できる。

---

## 5. レベルロードの処理フロー

1. `map` の各行・各文字を `legend` で引いてオブジェクト名の配列を取得
2. オブジェクト名に `defaultTags` があれば適用して ObjectInstance 文字列を生成
3. `puzzle` を構築
4. `GameData.initialGlobalState` と `LevelData.initialGlobalState` をマージ（レベルの値が優先）
5. `GameState` を返す

> 詳細は `docs/フレームワーク計画.md` セクション 7.5 を参照。
