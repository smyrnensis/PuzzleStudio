First Editing Loop


Change the level first, then the legend, then the rules. That keeps each edit visible:


Add a character to the level.


Map that character in legend.


Give the object a sprite.


Put it in a layer.


Add rules only after it appears correctly.













PuzzleStudio Documents


Metadata


Put display metadata near the top of the file.




title "Sokoban"
subtitle "A compact pushing puzzle"
author "Puzzle Author"
homepage "https://example.com"


title is the game name. subtitle, author, and homepage are optional.


Scene components named title or subtitle can display these values without repeating the text.












PuzzleStudio Documents


Puzzle Block


Use a puzzle block for one playable ruleset.




puzzle sokoban {
layers {
Goal
Player Box Wall
}

win_conditions {
all Goal on Box
}

rules {
input [ Player ] -> [ > Player ]
[ > Player | Box ] -> [ > Player | > Box ]
move
}

levels {
legend {
. = empty
# = Wall
P = Player
B = Box
G = Goal
}

level start
#####
#PBG#
#####
}
}


A puzzle usually contains layers, sprites, rules, win conditions, and levels.


Files can contain more than one puzzle when scenes need to switch between them.












PuzzleStudio Documents


Layers


Use layers to declare board objects and decide which objects exclude each other.




puzzle sokoban {
layers {
Goal Button
Player Box Wall
@Cursor @Hint
}
}


Objects in the same layer cannot occupy the same cell at the same time.


Most layers do not need names. Use a named layer only when you also want a selector alias:


layers {
solid = Player Box Wall
}


Then a rule can use solid to mean Player Box Wall.


Names starting with @ are display objects. They are useful for cursors, hints, highlights, and other objects drawn on top of play state.












PuzzleStudio Documents


Groups


Use groups to create selector aliases in one block.




groups {
pushable = Box Crate
@hints = @Cursor @Hint
}


Groups keep rules readable when several objects behave the same way.


rules {
[ > Player | pushable ] -> [ > Player | > pushable ]
}


Use a group name where you would otherwise list the same objects repeatedly.












PuzzleStudio Documents


Tags


Use tags to define ordered sets of object-name atoms for schema axes.




tags {
color = red blue
}

puzzle color_boxes {
layers {
Player Box:color Wall
}
}


Box:color expands into object identities such as Box:red and Box:blue.


When a tag set contains object-name atoms, a qualified selector appends the suffix to each atom. For example, pair:a with pair = A B resolves as A:a B:a.


Built-in tag sets include directions, horizontal, and vertical.












PuzzleStudio Documents


Legend


Use legend to map level characters to objects.




levels {
legend {
. = empty
# = Wall
P = Player
B = Box
G = Goal
* = Goal Box
+ = Goal Player
}
}


Each character used in a level map should have a legend entry.


One character can place multiple objects in the same cell, such as Goal Box.












PuzzleStudio Documents


Levels


Use levels to store playable maps.




levels {
level first
#####
#PBG#
#####

level second
#######
#P.BG#
#######
}


Each non-empty row after level <name> is read as level text until a blank line, another level, or the end of the block.


Use next_level from rules or lifecycle hooks to advance.












PuzzleStudio Documents


Level Local Legend


Use a level-local legend when one level needs extra characters.




levels {
legend {
. = empty
P = Player
}

level warehouse
legend {
x = Goal Box
}

P.x
}


The level-local legend only affects that level.












PuzzleStudio Documents


Messages


Use message to show text before or after a level map.




levels {
level intro
message "Push the box."
PBG
message "Room clear."
}


Messages before the map run when the level starts.


Messages after the map run when the level clears.












PuzzleStudio Documents


Rewrite Rules


Rules describe local state changes.




rules {
[ Player | Box ] -> [ Player | Crate ]
}


A rewrite has a left side, an arrow, and a right side.


Cells inside a row pattern are separated by |. A selector such as Player or Box matches an object in that cell.


Use no <selector> when a board cell must not contain an object. Use null when the pattern cell itself must be outside the stage.


rules {
once right [ no Edge | null ] -> [ Edge | ]
}


null is only an outside-board pattern atom. It is not an object, cannot be combined with other cell tokens, and is not written as no null.












PuzzleStudio Documents


Input Rules


Use input for rules that respond to directional input.




rules {
input [ Player ] -> [ > Player ]
}


input runs for up, down, left, and right.


> marks the direction on the matched object.












PuzzleStudio Documents


Movement


Use move after rules have marked objects with direction.




rules {
input [ Player ] -> [ > Player ]
[ > Player | Box ] -> [ > Player | > Box ]
move
}


The first rule marks the player. The second rule passes that direction to a box.


move applies the marked movement and blocks movement into occupied cells in the same layer.












PuzzleStudio Documents


Guards


Use if when a block should run only when a check is true.




rules {
if count(Box) == 0 {
next_level
}
}


The guarded block runs only when the condition is true.


Named conditions can also be used inside if.












PuzzleStudio Documents


Fix


Use fix when a group of rules should repeat or be limited together.




rules {
fix once {
[ Player | Coin ] -> [ Player | ]
[ Player | Key ] -> [ Player | ]
}
}


fix once applies each contained rewrite as a single match instead of repeatedly applying it.












PuzzleStudio Documents


Variables


Use variables for values that can change while the puzzle runs.






Basic Variables


var button_is_pushed = false
var moves = 0


var creates a named value. Rules and lifecycle blocks can update it.






Constants


const target_moves = 12
const door_color = "blue"


const creates a named value that stays the same.






Persistent Variables


persistent var cleared = false


persistent var keeps its value across normal restart and level load inside the current session.














PuzzleStudio Documents


Marks


Use marks for short-lived facts that help a rule chain run.






Declare Marks


marks {
visited
armed = bool
intent = directions
count = int
}


A bare mark name is a flag. A typed mark stores either a boolean, an integer, or one value from a named value set.






Mark Objects


rules {
[ Box ] -> [ Box{armed} ]
[ Box{armed} ] -> [ Box{no armed} ]
}


Marks can be added to objects and removed again inside rules.






Movement Intent


rules {
input [ Player ] -> [ > Player ]
move
}


Directional movement uses a temporary direction mark. move applies that direction after the input rule runs.














PuzzleStudio Documents


Conditions


Use conditions for named checks derived from the current board.






Count Objects


condition cargo_count = count(Box)


count(Object) returns how many matching objects are on the board.






Check Presence


condition any_goal = exists(Goal)
condition no_open_goals = none([ Goal no Box ])
condition some_box_on_goal = some([ Goal Box ])


exists, none, and some describe whether matching objects or patterns are present.






Use A Condition


rules {
if no_open_goals {
next_level
}
}


Use a condition name inside if when the same check should stay readable or be reused.














PuzzleStudio Documents


Win Conditions


Use win_conditions for checks that clear the current level.






Object Goals


win_conditions {
some Goal
all Goal on Box
}


This level clears when there is at least one Goal and every Goal has a Box on it.






Expression Checks


win_conditions {
exists(Goal)
none([ Goal no Box ])
}


Expression checks are useful when the clear condition is easier to read as board queries.






Multiple Lines


win_conditions {
all Goal on Box
no Enemy
}


Every line in win_conditions must be true before the level clears.














PuzzleStudio Documents


Scenes


Use scene blocks for screen flow outside the board.




scene title {
layout {
title
choice "Start" -> goto playing
}
}


Scenes can show text, menus, puzzle slots, and other layout components.


Use goto to move to another scene.












PuzzleStudio Documents


Scene Layout


Use layout only when the default puzzle screen is not enough.


Most single-board games do not need a layout block. A lone puzzle sokoban gets a playable screen automatically.




puzzle sokoban {
layout {
title
sokoban
}
}


The model name, here sokoban, displays that puzzle board.


Use an explicit scene when you need a title screen, menu, or level select screen.


scene title {
layout {
title
choice "Start" -> goto sokoban
}
}












PuzzleStudio Documents


Semantic Inputs


Use keys to map physical keys to named semantic inputs.




puzzle sokoban {
keys {
w ArrowUp -> up
s ArrowDown -> down
a ArrowLeft -> left
d ArrowRight -> right
r -> restart
}
}


The left side lists keys. The right side is the semantic input.


Rules and scenes use the action name.












PuzzleStudio Documents


Menus


Use choices and commands to build menus.




scene menu {
layout {
text "Menu"
column {
choice "Resume" -> input resume
choice "Restart" -> playing.restart
choice "Level Select" -> goto level_select
}
}

keys {
Escape Enter Space -> resume
}

routine resume {
goto playing
}
}


Use target-qualified commands such as playing.restart or board.restart when a command should operate on a specific target.












PuzzleStudio Documents


Lifecycle


Use on_* blocks for named moments in a puzzle or scene.




scene title {
on_scene_start {
stop_music theme
}
}


Common lifecycle hooks include on_scene_start, on_level_start, and on_level_clear.


Put setup, music, messages, and level advancement in the hook that names when they should happen.












PuzzleStudio Documents


Sprites


Use sprites to define how objects look.




puzzle sokoban {
sprites {
Box {
#b5651d #f4a261
00000
01110
01110
01110
00000
}
}
}


Colors come first. The following rows draw the sprite.


Use layers for collision and legend for level characters.












PuzzleStudio Documents


Display


Use display objects for rendered helpers such as floors, cursors, hints, and highlights.




puzzle sokoban {
layers {
Player Box Wall
@Floor
}

routine @fill_floor repeat {
[ no @Floor ] -> [ @Floor ]
}

on_display {
@fill_floor
}
}


Names starting with @ are display objects.


on_display can produce visual helpers without changing saved play state.












PuzzleStudio Documents


Theme


Use theme to set presentation colors. Themes expose only background_color, text_color, and accent_color; derived surfaces should use those colors with alpha instead of introducing extra theme colors.




theme clean {
accent_color #2f7d62
background_color #f7f5ef
text_color #1d2522
}


Themes set defaults for exported play surfaces.


Use sprites for object drawings and themes for surrounding presentation.












PuzzleStudio Documents


Sounds


Use sounds to name sound effects and music.




sounds {
sfx step seed=step type=step volume=0.45
sfx splash seed=splash type=water volume=0.7
sfx box_drag seed=box-drag type=drag volume=0.75
sfx clear seed=clear type=jump volume=1
music theme seed=main bpm=105 volume=0.5
}

puzzle sokoban {
sounds {
move Player -> sfx step
move Box -> sfx box_drag
}

on_level_clear {
sfx clear
next_level
}
}


Put movement sounds in the puzzle. Put scene music in scene lifecycle. Put clear sounds in level lifecycle.
