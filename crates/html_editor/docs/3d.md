# 3D
Use `puzzle` for a three-dimensional grid model. It uses the same `layers`,
`rules`, `levels`, and `visuals` concepts as a 2D puzzle; there is no separate
`levels3` syntax.

## Level Depth
A line containing only `-` starts the next Z layer in a 3D level. The `.`
character follows the shared `levels` contract: it is always empty and cannot
be remapped in either dimension.

## Camera And Viewport
```puzzle
puzzle push3d {
render {
camera {
orthographic = false
yaw = 34
pitch = 38
roll = 0
zoom = 1
interactive_look = true
interactive_zoom = true
}
grid {
type = "occupied_cells"
}
viewport {
smoothscreen 7 7
focus Player
}
pixelate {
enabled = true
scale = 4
smoothing = true
}
shade = true
shadow = true
}
}
```

`camera` defines the initial view. `orthographic = true` selects orthographic
projection; the default is perspective. `roll` rotates the image plane around the
view direction and defaults to `0`. Pointer look and zoom are component gestures,
not semantic puzzle inputs. `viewport` frames a world-space region around its
focus; it does not hide objects outside that region. `zoomscreen` snaps to the
target and `smoothscreen` follows it gradually.

`pixelate` is a canvas postprocess. `shade` controls voxel face shading, while
`shadow` enables cast shadows in the Three.js renderer. Shadows are disabled by
default and are not supported by the diagnostic Canvas renderer. A 3D object
without a visual is not given an implicit cube.

Rules may emit `set yaw = <angle>`, `set pitch = <angle>`,
`set roll = <angle>`, `set zoom = <number>`, or `reset_camera`. These are view
commands rather than saved puzzle variables.

## Voxel Visuals
3D visuals use `-` for the next -Z voxel layer and `>` for the next animation
frame. A color-only visual is a filled 1x1x1 voxel. Use `shape = <name>` to
reference a reusable voxel pattern from `shapes`.
