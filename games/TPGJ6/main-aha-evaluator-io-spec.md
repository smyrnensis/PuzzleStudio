了解。演繹可能性の軸を中心に据えて、評価器を self-contained に再生成する。発見順の痕跡を消し、I/O を固定し、ソルバ依存を排し、抽象段階で完結する形にする。

# メインのアハ評価器

## 0. これは何か

グリッドベースのパズルゲーム(倉庫番系)のメカニクス選定段階で使う判定器。盤面はまだ無い。実装もソルバも無い。**メカニクスのセットと、アハの抽象的な設計計画**を受け取り、それが良いメインのアハを生むかを、抽象空間(せいぜいトポロジー)だけで判定する。

この評価器は生成の仕様書も兼ねる。全ふるいを通過し連続量で高得点を取る候補を構成することが、「良いメインのアハを設計する」の操作的な意味になる。

---

## 1. 前提定義

**アハとは何か。**
メインのアハとは、**プレイヤーが既に内面化しているメカニクスシステムから演繹可能でありながら、まだ自分では演繹していなかった帰結に、自力で到達する瞬間**である。

この定義は四つの含意を持ち、それぞれがテスト群の根拠になる:
- 演繹**可能**だから、新情報の獲得ではない。システムは既知のまま、帰結だけが新しい。
- まだ演繹**していなかった**から、乗り換えの落差が生まれ、アハが発火する。
- **自力で**到達するから、設計者からの提示(受信)ではない。気づきの主体はプレイヤー。
- 事後に「考えれば自分も同じ結論に至った」と納得できるから、誠実であり、かつ賢くなった感覚を生む。設計者に騙されてもおらず、設計者の賢さに感心するのでもなく、自分の中に既にあった可能性に気づく。

**良い generalization と悪い generalization の区別(この評価器の中心軸)。**
アハは表現の乗り換え(P_wrong → P_right)として現れ、しばしば generalization(より広い見方への拡張)を伴う。決定的なのは generalization の有無ではなく、その**導出元**である:
- **悪い generalization**:それ以前のシステムから導出**できない**。設計者が外部から追加した新事実。プレイヤーは事後に「知らなかった、導けるわけがない」となる。受信。種類1。
- **良い generalization**:一貫したシステムの規則から**演繹可能な帰結**。設計者は新事実を足しておらず、プレイヤーが既に持つシステムから、まだ引き出していなかった帰結を引き出させただけ。プレイヤーは事後に「考えれば自分も至った」と納得する。種類2=メインのアハ。

**アハ候補は二つの表現の対として記述する。**
- **P_wrong**:プレイヤーが当該局面で握っている表現。次の二条件を**両方**満たす:
  - **(定義a:非明文)** ゲームのルールに明文化されていない。プレイヤーが習慣で補った「不在の制約」。明文化された制約は定義上 P_wrong になりえない(正しいルールであり迂回路が無いため)。
  - **(定義b:既正解)** 当該局面より前で実際に正解を与え続けてきた。一度も裏切られていないからこそ強固に握られている。
- **P_right**:乗り換え後の、正解が見える表現。P_wrong を**特殊例として包含する、より広い表現**(P_wrong ⊂ P_right)。P_wrong は「間違っていた」のではなく「狭かった」。乗り換えは誤りの訂正でなく、正しかった表現の拡張。

**誠実性の原則(全体を貫く制約)。**
- 盤面は一切嘘をつかない。全情報が正直に提示され、全要素が解に機能する。
- プレイヤーの詰まりの原因は、盤面の側(囮・誘導)でなく、プレイヤーの側(持ち込んだ不在の制約)になければならない。
- 設計者の唯一許される作為は「先回りの説明を足さないこと」。誤読へ誘導する要素を足すこと(レッドへリング)も、正解を予告する要素を足すこと(一般化の提示)も、ともに禁止。

---

## 2. INPUT / OUTPUT

**INPUT(すべて抽象。盤面配置・座標・手数は含まない):**
- `mechanics`:ルールの集合。各ルールはオブジェクトの決定的振る舞いを規定する。可能なら、個別物理の寄せ集めでなく、一貫した生成規則(例:Baba の `X IS Y`)として記述する。
- `plan`:アハの設計。以下を含む:
  - `P_wrong`:プレイヤーが握る非明文・既正解の制約。
  - `P_right`:乗り換え後の表現。
  - `setup_plan`:P_wrong を育て信頼させる助走の状況記述(トポロジー/状況レベル)。
  - `break_plan`:P_wrong が初めて尽き P_right が要求される状況記述(トポロジー/状況レベル)。

**OUTPUT:**
- `verdict`:ふるいの合否。失格なら停止したテストと理由。
- `quality`:連続量テストの程度。
- `design_constraints`:盤面設計段階で守るべき制約(評価器は判定せず、メカニクス選定の合否にも用いない。後段への持ち越し)。

---

## 3. 評価手順

1. 候補を (mechanics, plan) として記述。P_wrong が定義a・定義bを満たすことを確認(満たさなければ候補として不成立)。
2. **第1層ふるい(種別・誠実性)** を上流から適用。一つでも落ちたら verdict=FAIL で停止。
3. **第2層連続量(アハ性・質・射程)** を評価し quality に記録。
4. **design_constraints** を出力(盤面設計段階へ持ち越す制約)。

---

## 4. 第1層:ふるい(二値・INPUT のみで判定)

### S1 演繹可能性テスト(中心テスト・最上流)
`P_right`(乗り換え後の表現)は、プレイヤーが既に内面化している `mechanics` から**演繹可能な帰結**か、それともシステムから導けない**外部から追加された新事実**か。
- システムから演繹できない新事実(プレイヤーが事後に「知らなかった、導けるわけがない」となる)→ **FAIL**(悪い generalization=種類1=提示)。
- システムの一貫した規則から演繹可能な帰結(プレイヤーが事後に「考えれば自分も至った」と納得できる)→ 通過(良い generalization=種類2)。
- 判定法:`P_right` が要求する操作・帰結を、`mechanics` の明文規則から導出する経路が存在するか。存在すれば演繹可能。存在せず新ルールの追加が要るなら新事実。

### S2 P_wrong 定義検証
`P_wrong` が `mechanics` のどの明文ルールにも一致せず(定義a:非明文)、プレイヤーの習慣に由来するか。
- 明文ルールと一致する → **FAIL**(それは正しいルールで迂回路が無い。P_wrong として不成立)。
- 非明文かつ習慣由来 → 通過。
- 補助(帰責の確認):この P_wrong で詰まったプレイヤーに正解を示したとき、「書いてなかった/紛らわしい」と盤面へ帰責するなら囮(FAIL)、「明文ルールを読み落としていた」なら不注意(FAIL)、「書かれてもいない制約を自分が課していた」なら通過。

### S4 既正解テスト(定義bの計画検証)
`setup_plan` は、`P_wrong` を実際に正解として通用させる状況を含むか。
- 含まない(助走が無く P_wrong が育たない)→ **FAIL**(握る根拠が無く、握っていない表現は破れない)。
- 含む(複数の状況で P_wrong が勝ち、一度も裏切られない助走がある)→ 通過。
- 設計含意:アハは単一局面でなく「**助走(setup)→ 破壊(break)**」の対として設計する。

---

## 5. 第2層:連続量(INPUT のみで判定。程度を quality に記録)

### Q2 符号反転テスト(不可視性の素質)
`break_plan` における正解の第一手は、`P_wrong` の価値基準では負(無意味・損・禁止)と判定され、`P_right` の価値基準では正と判定されるか。
- 両表現で同符号(P_wrong でも手を出す価値があると見える)→ 格下げ(P_wrong のまま正解に手が伸びる=不可視性が無い)。
- 符号が反転する(P_wrong では出す気にならない手が P_right で正解になる)→ 高評価(不可視性の素質あり)。

### Q1 直視テスト(アハ性の素質)
`P_right` に乗り換えたとき、`break_plan` の正解手列は P_right の価値基準で各手が明白な選択として繋がるか(乗り換え=ほぼ解決)。それとも、P_right に立ってもなお非自明な探索が残るか。
- 探索が残る → 格下げ(プロセス/先読み寄り。乗り換えだけでは解けない)。
- 乗り換えれば直視できる → 高評価。

> Q2 と Q1 は対。**正解は、乗り換えれば直視でき(Q1)、しかし P_wrong の下では符号が負で見えない(Q2)。** この落差がアハの大きさ。手数の実測ではなく、メカニクスと計画が落差を生む構造的素質を持つかを問う。

### Q3 単一性テスト
`break_plan` が要求する乗り換えは一個か。
- 複数の独立した気づきの連鎖を要する → 格下げ(複合パズル。純度が低い)。
- 一個の表現転換で局面が氷解する → 高評価。

### Q4 包含テスト(質)
`P_right` は `P_wrong` を特殊例として包含するか(⊂)。
- 否定して置き換える(P_wrong は端的に間違いで捨てる)→ 格下げ(「騙されていた」に近づき S2 の不誠実側へ滑る)。
- 包含する → 高評価(視野が広がった/賢くなった感覚。過去の読みが否定されない)。

### Q5 積層テスト(射程)
`mechanics` と計画は、一度起きた P_wrong→P_right を、後のレベルで**新しい P_wrong として定着させ、再び別角度から破る**余地を持つか。
- 一回で消費されて終わる → 格下げ(一発ネタ)。
- 転換が語彙になり、その上にさらに演繹可能な帰結が積める → 高評価。
- 注:一貫した生成規則を持つ `mechanics` ほど、演繹可能な帰結を多産し、ここが強くなる(Baba の `X IS Y` 型)。

### Q6 汎用性テスト(射程)
`P_wrong` を多くのプレイヤーが共通して持つか、あるいは `setup_plan` で育てられるか。
- 一部の人しか持たない特殊な思い込み → 格下げ(アハが当たる人を選ぶ)。
- ほぼ全プレイヤーが持つ、または助走で全員に育てられる → 高評価。

---

## 6. design_constraints(盤面設計段階への持ち越し)

以下は具体盤面が無いと判定できず、メカニクス選定の合否には用いない。評価器は「空虚な申し送り(ソルバで検証せよ)」を出さない代わりに、盤面を作る段階で守るべき制約として明示する。

- **中立配置**:盤面の各要素について、解に機能しない要素(pruning で削除しても解が成立する要素)のうち、メカニクスの語彙に属する見た目でプレイヤーが解の一部と誤読しうるもの(レッドへリング)を置かない。明らかな背景・装飾は可。一般化を予告する視覚的合図も置かない。
- **自力構成**:乗り換えが盤面を一目見ただけで視覚的に露見しない配置にする(出口=押せる の失敗:配置が一目で一般化を露見させた)。乗り換えは試行と観察の往復から構成されるよう、誤読へも正読へも傾けずに配置する。

---

## 7. 構造一覧

| 層 | テスト | 種別 | 判定根拠(INPUT) |
|---|---|---|---|
| 1 ふるい | S1 演繹可能性 | 二値 | P_right が mechanics から演繹可能か |
| | S2 P_wrong定義検証 | 二値 | P_wrong が非明文・習慣由来か |
| | S4 既正解 | 二値 | setup_plan が P_wrong を育てるか |
| 2 連続量 | Q2 符号反転 | 程度 | 正解第一手の価値符号が P_wrong/P_right で反転するか |
| | Q1 直視 | 程度 | P_right で正解が直視できるか(プロセスでないか) |
| | Q3 単一性 | 程度 | 乗り換えが一個か |
| | Q4 包含 | 程度 | P_wrong ⊂ P_right か |
| | Q5 積層 | 程度 | 演繹可能な帰結を多産し再び破れるか |
| | Q6 汎用性 | 程度 | P_wrong が普遍的か |
| 持ち越し | 中立配置・自力構成 | — | 盤面設計段階で守る制約 |

ふるい(S1, S2, S4):二値、上流から適用、一つでも落ちれば FAIL。
連続量(Q1–Q6):程度を quality に記録。Q1×Q2 が落差(アハの大きさ)、Q4 が質、Q5・Q6 が射程。

---

## 8. 校正例

新候補を評価する前に、この較正で物差しを確認する。**注意:A Monster's Expedition の丸太は「良いアハの基準点」ではない。** 丸太の「障害物⊂地形(橋)」は system からの演繹ではなく外部追加に近い新事実(水に落とすまで橋になると導けない)であり、S1 で弱い/FAIL 寄り。入口に一度の気づきがあるが本体はプロセス(転がりの逆算)で、Q1 でも格下げ寄り。丸太を理想例に据えてはならない。

- **Baba Is You の `LEVEL IS rock`(メタパズル突入)**:S1 通過(`X IS Y` の一貫規則から `LEVEL IS rock` は演繹可能な帰結。「考えれば自分も至る」)。Q5 が極めて強い(一貫した生成規則が演繹可能な帰結を多産)。**良いメインのアハの基準点。**
- **A Monster's Expedition の丸太**:S1 弱い〜FAIL(system からの演繹でなく新事実寄り)、Q1 格下げ寄り(乗り換え後も転がり逆算のプロセスが残る)。**generalization の提示寄り。理想例にしない。**
- **Stephen's Sausage Roll**:genuine puzzle(プロセス)寄り。Q1 で格下げ傾向(正しい見方に立ってもなお長い手順探索が残る)。
- **「出口は押せる」**:S1 で FAIL(出口が押せることは従前システムから導出できない新事実)。
- **Sokobond / 減算型(能力を一つずつ失う)**:Q1 格下げ(プロセス)、減算型は Q2 も弱い(順序逆算は符号反転でなく先読み)。

これらの判定が直観と一致することを確認してから本番候補にかける。

---

## 9. 使用上の注意(生成器として使う場合)

- **生成の向きを固定**:先に (P_wrong, P_right) の対を全ふるい通過するよう構成し、その後にそれを成立させる最小 `mechanics` を逆算する。ルールを先に発明して後からアハを探さない。
- **一貫した生成規則を志向**:個別物理の二重性(丸太型)より、一貫した生成規則のシステム(Baba 型)を探す。後者は演繹可能な帰結を多産し、S1 を通過しやすく Q5 が強い。「locked にまつわる規則システムで、未演繹の必然的帰結を大量に内包するもの」を探すのが正道。
- **P_wrong は最も希少な資源**:ほぼ全員が持ち(Q6)、助走で育てられ(S4)、非明文で(定義a)、かつ system の演繹可能な帰結によって破れる(S1)もの。ここを起点に逆算する。
- **評価器は抽象の上限まで**:Q1・Q2 は落差を生む構造的素質を判定するが、手数の実測ではない。中立配置・自力構成は盤面設計段階の制約。評価器は触れられる範囲だけを誠実に判定し、それ以外は design_constraints として持ち越す。
